改了什麼
--------

frontend/build-fetch.js（新增）
  三個 plugin 共用的取資料邏輯。原本 seo / sitemap / prerender 各有一份
  fetchJson，全都是 catch 後 return null，plugin 收到 null 只 console.warn
  一行然後 return，build 的 exit code 仍是 0。

  - fetchJson：3 次嘗試、逾時 45 秒、間隔 15 秒
  - requireBuildData()：PRERENDER_REQUIRED 設了就讓 build 失敗
  - configProblem()：分開「沒設 VITE_API_URL」（本機／CI 的正常路徑）
    與「設了但打不通」（真正的故障），前者不該把 build log 洗成警告
  - reportMissing()：required 模式丟例外，否則印醒目區塊

render.yaml
  - buildCommand 前面加預熱 curl（`|| true`，喚醒失敗不擋 build）
  - build 帶 PRERENDER_REQUIRED=1

三個 plugin：改用共用模組，失敗處置換成 reportMissing。
sitemap 的完成訊息加印 lastmod 與分子頁筆數（原本只印總筆數，
而 issue 的症狀正是「123 筆看起來正常，其實這兩個都是 0」）。

驗證三：Render 會不會真的送出這些檔案
------------------------------------

這是整個修法的前提，而且從 #21 到現在從來沒被驗證過（因為預渲染沒跑過）。
render.yaml 有 `/* → /index.html` 的 rewrite，dist/stroy/H/index.html 會
不會被它蓋掉？

Render 官方文件（https://render.com/docs/redirects-rewrites）：

  "Render does not apply redirect or rewrite rules to a path if a resource
   exists at that path. Instead, Render simply serves the resource at that path."

目錄索引的部分，Render 社群討論確認 page1/index.html 同時對應 /page1
與 /page1/（https://community.render.com/t/static-site-redirecting-non-trailing-slash-urls-to-trailing-slash/3318）。

所以 /stroy/H 會拿到預渲染那份。順帶一提，兩種形式都通會構成重複內容，
但我們寫出的 canonical 是不帶尾斜線的 /stroy/H，這點已經處理掉。

→ 仍需部署後 curl 實測確認（見下方待辦）。


驗證四：CI 路徑沒被改壞
----------------------

CI 刻意不給 VITE_API_URL 與 VITE_SITE_URL，要走 fallback 路徑。

  $ npm run build          # 無任何環境變數
  [emit-sitemap] 未設定 VITE_SITE_URL，略過
  [inject-seo] VITE_API_URL 未設定，略過
  [prerender] 未設定 VITE_SITE_URL，略過
  ✓ built in 5.79s
  exit code: 0，dist/index.html 存在

一行訊息、不印醒目區塊——「沒設定」是本機與 CI 的正常路徑，不是故障。

          分子頁，/molecule/:slug 從來沒被提交給 Google；...

    處理：確認後端服務活著；免費方案的休眠請靠 buildCommand 的預熱請求

    已設定 PRERENDER_REQUIRED，中止 build。
  ============================================================================

  x Build failed in 35.43s
  exit code: 1

這是 issue 裡「最重要」的那一條：SEO 靜默壞掉變成部署失敗。
